Glossary

Short definitions of the concepts used on this blog. See how they connect on theconcept map.

A

AGENTS.md
A Markdown file in a repository that gives coding agents project instructions, such as commands, conventions and rules. CLAUDE.md plays the same role.
Autoregressive decoding
How LLMs generate: one token at a time, each conditioned on the tokens before it. Structured JSON is generated the same way.

B

Bootstrap interval
A range for a measured number, found by resampling the examples with replacement many times and seeing how much the number moves.
Brier score
The mean squared gap between predicted probabilities and 0/1 outcomes. Lower is better, and confident mistakes cost the most.

C

Calibration
Whether probabilities match outcomes: among many answers given probability 0.8, about 80% should be right. Measured over many predictions.
Choice
A question type that picks one option from a defined set of up to 255, returning the probability of every option and a confidence.
Coding agent
An AI system that edits a codebase in a loop: a model reads files and command output, calls tools, and proposes or makes changes.
Compaction
Summarising an agent's long history into a shorter version so the session fits in the context window. It's lossy, and done without knowing the next question.
Confidence
A number from 0 to 1 computed from an answer's probability distribution. High when probability is concentrated; it doesn't say the answer is right.
Context engineering
Deciding what goes into a model's context on each turn: which files, results, instructions and history it sees, and in how much detail.
Context window
The most input a model accepts in one request. Jev allows 64K tokens, with 32K for the state plus the longest question.

E

Encoder model
A transformer that reads its whole input at once, in both directions, and outputs representations instead of generating text. BERT is the classic example.
Entropy
A measure of how spread out a probability distribution is: zero when all probability is on one answer, highest when it is uniform.
Expected calibration error
How far stated confidence sits from observed accuracy, averaged over confidence bins. 0 means perfectly calibrated; lower is better.

F

Fine-tuning
Training an existing model further on labelled examples from your own task, so it does better on that task.
Frontier model
The most capable, and usually most expensive, models a provider offers. In a coding agent, the one trusted with planning and hard steps.

G

Guardrail
A check that screens an input, an output or a proposed action such as a tool call, before it is allowed to proceed.

H

Harness
The code around a model in an agent: it builds each turn's context, runs the tools the model asks for, and applies rules and permissions.

J

Jaggedness
TypeSafe's name for Jev's known weak spots, such as counting, arithmetic, date comparison and reading instructions too literally.
Jev
TypeSafe's System One model. It answers typed questions about an input with probabilities, and can't generate text.

K

KV cache
Stored attention keys and values for text a model has already processed, so an identical prefix doesn't have to be computed again.

L

Latency
The time a request takes from sending to answer. Usually reported as the median and a slow-tail percentile such as p90.
Laya
An open-weights decision model from Convai Innovations. It takes Jev's request shape (noul, choice, score) and runs on your own hardware.
LLM
Large language model: a model trained to predict the next token, used to generate text, code and structured output.

N

Noul
A yes/no question type. The answer is the probability that the answer is yes, from 0 to 1. Nouls carry no separate confidence.

O

Open weights
A model whose trained parameters you can download and run yourself, as opposed to one you can only reach through a vendor's API.

R

Reranking
Re-ordering retrieved candidates by a relevance score, so the best ones reach the answering model first.
RLCD
Reinforcement learning for calibrated decisions: TypeSafe's training approach for models that return decisions with calibrated probabilities.
Routing
Sending each request to the right handler, such as a model, an agent, plain code or a person, based on a quick classification.

S

Score
A question type that rates the input on ordered levels you describe. The score is the probability-weighted mean of the level numbers.
Speculative fan-out
Asking every question you might need in one request, then letting code decide which answers matter, instead of chaining calls.
State
The input a System One model evaluates: a string, a JSON object or an array of text. Every question in a request is asked about the same state.
Structured outputs
Getting machine-readable answers (JSON, enums, numbers) from a model instead of free text, so code can use them directly.
Sub-agent
A second agent started by the main one to handle a subtask with its own context, whose result is then merged back.
System One model
A model that makes fast, structured decisions: it evaluates an input against typed questions and returns probabilities instead of text.

T

Temperature scaling
Fixing over- or under-confident probabilities by dividing a model's log-probabilities by one fitted number, the temperature, before the softmax.
Token
The unit of text a model reads and writes, usually a word or part of one. Prices and context limits are counted in tokens.
Tool calling
A model asking the harness to run a named function, such as grep or the tests, with structured arguments, then reading the result.

V

Visibility ladder
Showing each piece of an agent's context at one of a few levels (hidden, short, long or full), decided per question rather than once for all.

Z

Zero-shot
Using a model on a task with no examples and no training for it: only the instructions and the options in the request.
